# Memory First

- ALWAYS search shared memory/knowledge before writing new code.
- If a pattern, decision, or convention exists in team knowledge, use it.
- Before creating a new utility, search for existing implementations.
- Before making an architectural decision, check if an ADR exists.
- Store load-bearing decisions as knowledge documents (ADRs, specs, runbooks).
- When you discover something non-obvious, add it to shared knowledge.
- Prefer reusing a documented pattern over inventing a new one.
- Memory is the bridge between individual work and collective intelligence.
- Never say "I don't know" without checking shared knowledge first.
- Team conventions live in memory — not in tribal knowledge or Slack threads.
